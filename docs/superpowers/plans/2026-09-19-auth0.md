# Auth0 Implementation Plan

**Goal:** Require Auth0 login and isolate each user's Nourish diary.

**Architecture:** Use the official server SDK through vinext's proxy support.
Authorize at each API handler and use the verified subject as the storage key.

**Spec:** `docs/superpowers/specs/2026-09-19-auth0-design.md`

## Constraints

- Preserve the Cloudflare/D1 runtime and Docker persistence.
- Configure secrets at runtime; build without tenant credentials.
- Never accept identity headers or a shared fallback identity.
- Do not claim legacy data automatically.

## 1. Session and authorization boundary

- [x] Install the official Auth0 SDK and a test runner.
- [x] Add API regression tests that currently fail: anonymous/forged requests
  return 401, reads and writes use the session subject, and cross-origin writes
  return 403 before accessing storage.
- [x] Add `lib/auth0.ts`, `lib/auth.ts`, and `proxy.ts`; replace identity lookup
  in all five API route modules. Keep existing validation and storage behavior.
- [x] Verify tests, including missing config and invalid/expired cookies.

## 2. User flow and runtime configuration

- [x] Gate `app/page.tsx` on the server session and add a signed-out screen.
- [x] Add account/sign-out controls and expired-session handling to the app.
- [x] Delete the obsolete ChatGPT helper and disable simulated development auth.
- [x] Add `.env.example`, Docker runtime configuration, and setup instructions.
  Exclude secrets from Docker context and keep callback failures generic.

## 3. Verify and document

- [x] Run `pnpm test`, `pnpm exec tsc --noEmit`, `pnpm lint`, and `pnpm build`.
- [x] Smoke-test the compiled Worker and add current-source CI authentication checks.
- [x] Review the diff for secret handling, per-user access, redirects, and cache
  behavior. Record any existing failures and external configuration still needed.

## Verification results

- 16 tests pass, including a full OAuth authorization-code/PKCE exchange against
  a local test double of the provider, state/nonce rejection, and logout.
- TypeScript and the production build pass. The compiled Worker smoke test
  passes with encrypted sessions, isolated users, writes, trends, and CSRF.
- Lint reports six pre-existing errors: three `no-explicit-any` violations in
  food search and three `set-state-in-effect` violations in the app. Running
  ESLint on the corresponding `HEAD` files confirms the same errors.
- Independent read-only review found no actionable issues. Build output was
  checked for accidental inclusion of the local session-encryption secret.
- Live Auth0 discovery works. Real tenant login/logout still needs the client
  secret in `.env.local` and registered localhost callback/logout URLs.
- The historical container-validation workflow still tests published v1.0.0.
  A new checks workflow builds and smoke-tests current source without credentials.
