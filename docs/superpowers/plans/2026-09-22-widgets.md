# Widgets Implementation Plan

> Execute inline using the executing-plans and test-driven-development skills.

**Goal:** Add iPhone/iPad Home Screen and Lock Screen widgets and Android Home Screen widgets.
**Architecture:** Native views consume a versioned aggregate snapshot. Existing diary storage remains authoritative. A local Expo module publishes snapshots; the iOS Siri actions share the Swift publisher.
**Tech Stack:** TypeScript, Expo modules/config plugins, SwiftUI/WidgetKit, Kotlin/RemoteViews.
**Spec:** `docs/superpowers/specs/2026-09-22-widgets-design.md`.

## Constraints

- Preserve current database paths and the installed native deployment floors.
- Share aggregate nutrition/water values only. All widget taps open today's diary.
- Atomic publication, refresh after committed changes, and explicit stale/unavailable states.
- No network calls or direct logging inside widgets. Keep web builds working.
- Rebuild both native apps; provision the iOS extension and App Group through EAS.

## Execution decisions and progress

- User approved the spec and explicitly requested implementation; continue inline without another approval handoff.
- Existing linked worktree is already isolated. No new worktree required.
- iOS Expo module compiles the same core Swift sources as the Siri app target; publication uses a shared file lock to synchronize both copies. Android uses repository-computed summaries.
- Android resources and receivers ship in the autolinked local module rather than being copied into the generated app by a config plugin. Native manifest merging keeps repeated prebuilds clean.
- Full iOS compilation caught a Swift module-name collision between the extension and bridge pod. The extension now uses `GramelloWidgetExtension`; its public target/bundle identifier remain stable.
- Independent review identified Android RemoteViews inflation, minimum-API date compatibility, and stale accessibility-description defects. Regression tests cover their fixes.

- Integrated the latest main before opening the PR. Food-entry edits now trigger publication, with a regression test for updated nutrition and failed edits.
- Completed: 252 repository tests, 36 Swift tests, 6 Android tests, TypeScript/lint, native exports, full iOS simulator build, full Android debug APK, packaged extension/provider checks. Remaining signed-device checks are recorded in `docs/widgets-validation.md`.
