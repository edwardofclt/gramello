# Nourish Mobile Implementation Plan

**Goal:** Build an iOS/Android Nourish companion with gluestack-ui and shared Auth0 accounts/data.

**Architecture:** An Expo app in `mobile/` calls existing APIs with Auth0 access
tokens. The API supports both existing web cookies and verified mobile tokens.
UI, auth, API requests, and nutrition math have separate modules.

**Tech Stack:** Expo 57, React Native 0.86, TypeScript, gluestack-ui core 5,
react-native-auth0 5, jose, Vitest.

**Spec:** `docs/superpowers/specs/2026-09-19-mobile-design.md`

## Constraints

Preserve cookie auth and CSRF protection. Mobile never contains server secrets.
Use the same verified Auth0 subject and existing API/data model. Implement all
core flows with real data and explicit errors. Work in the existing worktree.

  offline dependency matrix check passes; newer Expo patches remain outside the
  repository's seven-day dependency window.
- The Expo/React Native Web Playwright flow passes at 390 x 844: sign in, search,
  exact-gram food logging, coupled goal save, trend ranges, delete, sign out.
  Screenshots were inspected in `test-results/mobile-*.png` (ignored artifacts).
- Scoped source review findings were fixed and re-reviewed: required JWT expiry,
  normalized SDK credential errors, session generation/secure-store ordering,
  foreground draft preservation, and native-client/M2M claim rejection.

Repository-wide lint still reports eight existing errors in unchanged web food
search, web state effects, and the old web Playwright fixtures. It is not a clean
full-repository lint run. Native Auth0 callbacks, keychain/keystore restoration,
and device login require a configured tenant and a native development build;
these were not exercised against a live account. No external Auth0 settings,
web deployment, signing, or store publishing were changed.
