# Browser tests

Install dependencies, build the main web app, and run the actual browser worker:

```bash
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm test:e2e
```

The disposable Worker runs at http://127.0.0.1:5198 with a temporary database for
hosted-diary migration/export. The main diary itself uses real SQLite WASM,
IndexedDB, and Web Locks. Each test uses a fresh browser context. The server
applies migrations and removes its temporary database when the run ends. Never
point these tests at production.

Desktop and phone Chromium projects cover food and recipe portions, custom foods,
entry edits and removal confirmation, water, goals, charts, narrow dialogs,
reload persistence, and deterministic Open Food Facts fixtures. These fixtures
do not certify live provider availability.

`browser-local.spec.ts` additionally verifies a backup generated by the native
repository, browser export round trips and recovery, actual offline reload and
bundled-catalog food logging, cross-tab write serialization, browser isolation,
and full-history hosted migration without server deletion. The native fixture
in `tests/fixtures/native-browser-parity.gramello` was exported by the unchanged
`createLocalRepository` implementation; tests adjust diary dates to the local day.

`PLAYWRIGHT_BASE_URL` skips server setup and requires an explicitly configured
disposable instance. Screenshots and failure traces are saved under
`test-results/`; inspect failures with `pnpm exec playwright show-report`.

Native file pickers, camera permission handling, and OS share sheets still need
physical iOS/Android checks. Browser parity does not include Siri integration.
